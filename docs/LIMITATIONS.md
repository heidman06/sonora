# LIMITATIONS & preuves non disponibles — Sonora v2.1/v2.2

- **Mobile réel mi-gamme** : non disponible dans la session. Gate A1.0 et CA perf mesurés en surrogate desktop Chrome headless, viewport 390×844, CPU throttling ×4, marqués « NON VÉRIFIÉ MOBILE RÉEL » (docs/perf/DECISION.md). Résultat surrogate : 0 longtask > 100 ms, frame médian 16,7 ms ⇒ jank non confirmé ; le socle S0 (TrackList/DOM ≤ 100) est conservé car fondé sur des faits structurels, le sélecteur est conservé par tie-break documenté (design échelle §N5). Une passe appareil réel est requise avant release publique.
- **iOS réel (HLS arrière-plan, sleep écran verrouillé, vitesse masquée, paroles synchro HLS, SW en PWA standalone)** : non disponible. Vérifié en emulation : file HLS servie (m3u8 durées réelles), temps relatif utilisé par sleep/crossfade/paroles, SW actif + boot offline en headless. Le filet « ended » capture et les limites de bridage OS sont documentés (design features §F2).
- **CarPlay réel (Amperfy)** : non disponible. getSimilarSongs2/star/scrobble vérifiés par tests API (non vide < 500 ms à froid, métadonnées remplies, ordre position parity mus/Subsonic).
- **Crossfade audible / relais ≤ 100 ms** : mesurable seulement à l'écoute ou par enregistrement audio ; vérifié par tests unitaires (armement, rampe, abandon, révocation blob) + relais depuis cache HTTP/blob. CA audio final à passer sur appareil réel.
- **ntfy bout-en-bout** : vérifié sur la machine (messages postés puis « rétabli », dédup 6 h). Deux fausses alertes ont été émises pendant la mise au point du parseur systemctl (oneshot inactive / timestamp) puis corrigées et suivies d'un « rétabli » ; bruit one-shot documenté.
- **Sweep i18n 18 combos** : les SecurityError localStorage observés proviennent du script d'injection CDP sur about:blank (origine opaque), pas de l'application ; preuve : chargement invité sans injection = 0 exception, et 0 fuite FR / 0 erreur applicative sur les 18 combos.
- **Revue finale Goldfish (18 constats)** : tous corrigés en v2.2.1 — filet ended capture du sleep, garde sleep×crossfade (shouldArm + abandon à échéance + relais repause), rehydratation TrackList lue une fois au montage + persistance post-hydratation, defaultPlaybackRate (vitesse persistée à travers load()), sémaphore recos sans double prise, radioImmediate sans court-circuit du warm, undo avec toast d'échec + ordre reconstruit depuis l'état courant, classe playing réalignée, batchSize 20 sur les téléchargements (DOM page ≤ 100), saveQueueAsPlaylist via bulk, tests resolver ordre + statsPour invalidation/NULLIF + sleep ended + crossfade sleep, artefacts docs/perf et captures commis, sélecteurs média #sonora-media/#sonora-fade, SW meta-cache (pas d'auto-purge), palette négative non mémorisée, registerSw depuis main.tsx, compte à rebours sleep en-tête lecteur, /stats GET-only, reliquats audio/hls nettoyés, test i18n des clés dynamiques.
- **Mixes personnalises (v2.4.0)** : le nombre de mixes depend du corpus local (8-12 sur corpus diversifie, moins sur corpus mono-artiste ; le compte heid en avait 7 a la livraison) ; seuls les daily sont enrichis par le warm (ytsearch40, cooldown 6 h, 1 slot pool, jamais de relance des recos) ; la frontiere de jour est UTC (seed dans la reponse) ; les mixes mood/boucle/favoris/archives sont bornes par le corpus ; deco recouvre volontairement les autres mixes (mix decouverte) ; la page legacy garde le contrat v1 (3 mixes, noms FR).
- **Moods personnalises (v2.3.0)** : la langue des moods suit l'interface, pas le contenu ecoute ; un gout hors marche (rock ES / rap US en interface FR) n'est couvert que par les chips artiste (R6b du design) ; la tete peut rester stable plusieurs semaines (choix produit assume, fraicheur via chips artiste + invalidation like/feedback + TTL 30 min) ; la carte artistes (~120 tetes) est une donnee statique versionnee, extensible sans migration.
- **File HLS et navigateurs** : Chrome et Android repondent maybe au test canPlayType HLS sans lecture native ; depuis v2.2.5 la file HLS est reservee a iOS/Safari (vendor Apple + probably). Sur Chrome desktop/Android le mode direct reste actif : next/prev/seek/vitesse/crossfade/repeat pleinement fonctionnels. Verifie par sweep de 51 clics reels + 7 checks de comportement (repeat-one, repeat-all, lire-ensuite) sur la prod v2.2.5.
- **i18n clés dynamiques** : la règle de test combine un scan d'attributs (emptyKey/titleKey/hintKey/labelKey) et une union explicite des clés calculées connues (seed*, smart*, actions du menu ⋯, états vides). C'est un **filet figé**, pas une preuve de couverture exhaustive : toute nouvelle clé dynamique non littérale devra être ajoutée à l'union (tr() retombe sinon sur la clé brute).
